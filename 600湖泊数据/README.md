# 600 湖泊数据

本目录收录用户指定的完整数据交付：训练集 300 湖、测试集 300 湖，
共 611 个原文件（609 个 CSV、2 个原始读取示例）。原始总大小为
15,485,071,290 字节。训练/测试归属和原文件内容保持不变。

小于等于 10 MiB 的文件直接保存。更大的 CSV 使用无损 gzip 压缩，
通过 Git LFS 管理，文件名增加 `.gz`。全部文件上传前均通过
解压后 SHA256 和原始字节数核验。`manifest.json` 记录原路径、仓库路径、
文件大小和 SHA256。该存储方式允许逐湖修改及版本管理。

## 下载与读取

先安装 Git LFS，然后在克隆的项目中运行：

```shell
git lfs install
git lfs pull
python tools/lake600.py unpack ../600湖泊数据_工作副本
```

还原需要约 15.5 GB 可用空间。命令按原目录结构还原并校验每个文件，
可用 `--file "训练集/完整观测/洲/文件名.csv"` 只还原一个文件。
也可使用支持 gzip 的程序直接读取 `.csv.gz`，例如 `pandas.read_csv`。

## 修改并提交

拥有仓库写权限的协作者可创建分支，修改工作副本，然后提交 PR：

```shell
git switch -c data/update-lake
python tools/lake600.py pack ../600湖泊数据_工作副本 --file "训练集/完整观测/洲/文件名.csv"
git add -- "600湖泊数据"
git commit -m "Update lake observations"
git push -u origin data/update-lake
```

将示例路径替换为 `manifest.json` 中的实际 `path`。可以重复指定 `--file`；
不指定时处理全部 611 个文件。`pack` 更新对应文件及清单中的字节数、SHA256。
修改直接保存在仓库中的小 CSV 后，也应从更新后的工作副本执行 `pack`，
使清单同步。大文件修改后会存储一个新的 LFS 版本。

GitHub 网页可编辑小型文本文件；大文件应在本地还原、修改、打包后提交。
现有写权限协作者不需要额外的数据目录权限。其他贡献者可 fork 后提交 PR；
新增直接写权限由仓库所有者在 Settings → Collaborators 中授予。

## 文件与原清单

原清单中部分路径仍使用 `01_完整观测`、`03_温跃层FNO专项` 等旧目录名，
而本次交付实际观测文件位于 `训练集/完整观测/`、`测试集/完整观测/`。
应以 `manifest.json` 的路径为准。原清单引用的冬季 CSV 和 FNO NPZ
没有包含在用户指定的源目录中，本次交付也不包含这些文件。
两个 `FNO数据读取示例.py` 保留原字节，仅在另行提供对应 NPZ 后可使用。

这些数据属于观测资料，上传不改变模型的数据输入约束、训练/测试划分或科学状态。
仓库代码的 MIT 许可证不自动覆盖外部观测数据；来源信息见原始清单和观测字段。
